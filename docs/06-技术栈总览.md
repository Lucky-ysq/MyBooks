## 1. 后端技术栈

### 1.1 Spring Boot 2.7.18（后端主框架）

| 项 | 内容 |
|---|---|
| 是什么 | Spring 的「开箱即用」版本。自带内嵌 Tomcat，`main` 方法一跑就是个 Web 服务器，不用单独装 Tomcat、不用配 web.xml |
| 项目里干什么 | 提供 `/api/**` 这些 HTTP 接口，接收 App 的请求并返回 JSON |
| 为什么选它 | 和你正在学的 SSM（Spring + SpringMVC + MyBatis）最接近，只是把配置自动化了。学过 SSM 上手最快 |

**关键概念对照（SSM → Spring Boot）：**

| 你学过的 SSM | 本项目 Spring Boot |
|---|---|
| `web.xml` 配 DispatcherServlet | 不用配，启动类 `BooksApplication` 自带 |
| `applicationContext.xml` 一堆 bean | `application.yml` 几行搞定 |
| 手动配 Tomcat | 内嵌 Tomcat，`java -jar` 直接跑 |
| `@Controller` | `@RestController`（返回值自动转 JSON） |

**项目里的启动类**（`BooksApplication.java`）：

```java
@SpringBootApplication   // 一个注解 = 开启自动配置 + 扫描本包及子包的所有组件
public class BooksApplication {
    public static void main(String[] args) {
        SpringApplication.run(BooksApplication.class, args);  // 启动内嵌 Tomcat
    }
}
```

**配置文件** `src/main/resources/application.yml`（比 XML 直观）：

```yaml
server:
  port: 8080                     # 端口
spring:
  datasource:
    driver-class-name: org.sqlite.JDBC
    url: jdbc:sqlite:data/mybooks.db   # SQLite 就是这么一个文件
```

> ⚠️ **本机开发踩过的坑**：宿主环境注入了一个 `SERVER__PORT` 环境变量，Spring Boot 会把它当端口用，导致服务不监听 8080。所以本机启动要显式指定端口：
> `java -jar target/books-1.0.0.jar --server.port=8080`（命令行参数优先级最高）。

### 1.2 Spring MVC / REST 接口（Controller 层）

**是什么**：Spring 里处理 HTTP 请求的那一层，靠注解把 URL 映射到方法。

**项目里的三种写法**（`SourceController.java` 等）：

```java
@RestController          // = @Controller + @ResponseBody，方法返回对象自动转 JSON
@RequestMapping("/api/sources")   // 这个类下所有接口都带 /api/sources 前缀
public class SourceController {

    @GetMapping                      // GET /api/sources        → 查列表
    public Result list() { ... }

    @PostMapping                     // POST /api/sources       → 新增
    public Result save(@RequestBody BookSource source) { ... }   // @RequestBody：把请求 JSON 转成对象

    @PutMapping("/{id}")             // PUT /api/sources/1      → 修改
    public Result update(@PathVariable Long id, @RequestBody BookSource source) { ... }

    @DeleteMapping("/{id}")          // DELETE /api/sources/1   → 删除
    public Result delete(@PathVariable Long id) { ... }

    @GetMapping("/{id}/test")        // GET /api/sources/1/test?keyword=斗破
    public Result test(@PathVariable Long id,
                       @RequestParam(defaultValue = "斗破") String keyword) { ... }
}
```

**要记住的注解（就这几个）：**

| 注解 | 作用 | 记忆点 |
|---|---|---|
| `@RestController` | 标记这是接口类 | 返回对象 → JSON |
| `@RequestMapping` | 类级/方法级路径前缀 | 写在类上定前缀 |
| `@GetMapping` / `@PostMapping` / `@PutMapping` / `@DeleteMapping` | 对应 HTTP 的查/增/改/删 | 和 RESTful 一一对应 |
| `@PathVariable` | 取 URL 里的 `{id}` | 路径上的变量 |
| `@RequestParam` | 取 `?keyword=xxx` | 问号后面的参数 |
| `@RequestBody` | 取请求体 JSON | POST/PUT 传对象时用 |

**统一返回格式**（`common/Result.java`）：所有接口都返回同一个壳，App 端好处理：

```json
{ "code": 0, "msg": "ok", "data": ... }   // code=0 成功，非 0 失败（msg 是人话错误信息）
```

> 这是**后端接口设计的好习惯**：不要让每个接口返回长不一样，前端判断 `code===0` 就够了。

### 1.3 MyBatis-Plus 3.5.3.2（持久层 / 操作数据库）

**是什么**：MyBatis 的增强版。你在学的 MyBatis 要写 SQL、写 XML；MyBatis-Plus 对**单表增删改查**直接送你现成方法，不用写 SQL。

**项目里干什么**：管理「书源表」（`book_source`）的增删改查。

**三层结构（和 SSM 完全一样，只是更省事）：**

```java
// ① 实体：一个类对应一张表（@TableName 指定表名）
@Data                       // Lombok 注解，自动生成 getter/setter
@TableName("book_source")
public class BookSource {
    @TableId                     // 主键
    private Long id;
    private String name;         // 书源名
    private String baseUrl;      // 小说站网址
    private String rules;        // 解析规则（JSON 字符串）
    private Boolean enabled;     // 是否启用
}

// ② Mapper：继承 BaseMapper，白送一堆方法，一行不用写
public interface BookSourceMapper extends BaseMapper<BookSource> { }

// ③ 用的时候（Service 里注入）
mapper.selectList(null);              // 查全部
mapper.selectById(1L);                // 按主键查
mapper.insert(source);                // 新增
mapper.updateById(source);            // 按主键改
mapper.deleteById(1L);                // 按主键删
```

**BaseMapper 白送的方法（单表够用）：**

| 方法 | SQL 等价 | 说明 |
|---|---|---|
| `selectList(wrapper)` | `SELECT * FROM t WHERE ...` | 条件查列表 |
| `selectById(id)` | `SELECT * FROM t WHERE id=?` | 按主键查 |
| `insert(entity)` | `INSERT INTO t ...` | 新增 |
| `updateById(entity)` | `UPDATE t SET ... WHERE id=?` | 按主键改 |
| `deleteById(id)` | `DELETE FROM t WHERE id=?` | 按主键删 |

> **对比记忆**：MyBatis 你写 Mapper 接口 + XML 写 SQL；MyBatis-Plus 只写接口继承 `BaseMapper`，SQL 它替你生成。**复杂 SQL 还是可以自己写**，只是本项目单表够用。

**`application.yml` 里的配置**：`map-underscore-to-camel-case: true` 让数据库的 `base_url` 自动对应 Java 的 `baseUrl`；`id-type: assign_id` 表示主键由雪花算法生成（不依赖数据库自增）。

**Lombok**（`@Data`）：编译时自动生成 getter/setter/toString，省掉一堆样板代码。本项目用它简化实体类。

### 1.4 SQLite 3.44（数据库）

**是什么**：一个**单文件数据库**。整个数据库就是磁盘上一个 `.db` 文件，不用装数据库软件、不用启动服务。

**项目里干什么**：存书源规则（唯一一张表 `book_source`）。数据文件是 `backend/data/mybooks.db`。

**为什么选它**：
- 服务器零安装（省事，不用装 MySQL、不用配账号密码）
- 数据就是**一个文件**，备份/迁移直接拷文件
- 单表、数据量小（就几条书源），SQLite 绰绰有余

**Java 连它**：靠 `sqlite-jdbc` 驱动，写法和你学 JDBC 一样，只是数据库换成了文件：

```
url: jdbc:sqlite:data/mybooks.db      # 就这一行，指向一个文件
```

> **注意 MySQL 和 SQLite 的区别（用到了才关心）**：SQLite 没有独立的自增 `AUTO_INCREMENT`，主键用 `INTEGER PRIMARY KEY`；没有用户/权限概念。本项目主键用 MyBatis-Plus 的雪花算法生成，不依赖数据库自增，所以两边通用。

### 1.5 Jsoup 1.17.2（网页抓取解析）

**是什么**：Java 最常用的 HTML 解析库 —— 把网页 HTML 变成一棵可以「按选择器查找」的 DOM 树。

**项目里干什么**（后端的核心）：去小说网站抓页面，再按书源规则从 HTML 里抠出「书名/作者/目录/正文」。

**基本用法（三行看懂）：**

```java
Document doc = Jsoup.connect("https://某小说站/book/1.html")
        .userAgent("Mozilla/5.0 ...")     // 伪装成浏览器，很多站会拦非浏览器请求
        .timeout(20000)
        .get();                            // 发请求拿到页面

Element box = doc.selectFirst("#content");  // 按 CSS 选择器找元素
String text = box.text();                   // 取它的文本
String href = box.attr("abs:href");         // 取属性（abs: 前缀 = 自动补全成完整 URL）
```

**要会的选择器语法**（和前面 Web 前端 CSS 选择器同一套，学一次到处用）：

| 写法 | 意思 |
|---|---|
| `#id` | id 等于某值 |
| `.class` | class 包含某值 |
| `tag` | 标签名，如 `a`、`div` |
| `.a .b` | .a 里面的 .b（后代） |
| `a[rel=chapter]` | 属性条件 |
| `p:eq(0)` | 第 0 个 p（类似下标） |
| `a@href` | 取 a 的 href 属性（本项目自定义语法，非 Jsoup 原生） |

**本项目封装的两个工具类：**

- **`util/JsoupFetcher.java`**：统一抓取入口。做了三件实用的事：
  1. 统一 UA / 超时 / Referer（伪装浏览器，绕防盗链）
  2. **全局信任 SSL 证书**（小说镜像站证书链普遍不全，不信任会直接抓失败）
  3. 失败自动重试 1 次（镜像站偶发抽风）
- **`util/RuleParser.java`**：把「规则字符串」作用到元素上取值。支持 `a@href`（取属性）、`text`（取自身文本）、`own`（只取自身文本不含子标签）、逗号分隔多规则依次尝试。

> **抓网页的三个常见坑（都踩过）**：
> 1. **相对地址**：网页里 `href="/book/1.html"` 是相对路径，必须补成完整 URL，否则 App 拿到没法用
> 2. **编码**：有的站是 GBK，必须按站点编码处理，否则中文乱码（Jsoup 的 `execute().parse()` 会读页面 meta 自动识别）
> 3. **防抓取**：有的站把正文用 JS + base64 加密藏起来（本项目就遇到，见下）

**本项目的三个「高级适配能力」**（写在 `BookService.java` 里，因为真实站点太花）：

1. **目录翻页**：有的站目录不在详情页，还可能分 100 章一页 → 按 `nextPage` 选择器循环抓取拼接
2. **正文翻页 + 安全停止**：章内还分页（`5027049.html` → `5027049_1.html`），自动拼接；但**末页的「下一页」会指向下一章**，所以用「文件名 + `_数字`」正则判断，一旦不是本章分页就停，防止把整本书拼进来
3. **script base64 解码**：正文被藏在 `<script>` 里的 base64 串中 → 正则抠出 base64 → 解码 → 当正文

### 2.1 uniapp + Vue3（前端主框架）

| 项 | 内容 |
|---|---|
| 是什么 | 一套「用 Vue 语法写一次，能打包成安卓 App / 小程序 / H5」的框架 |
| 项目里干什么 | 写「遇夏小说」的安卓 App 界面 |
| 为什么选它 | 只写 Vue（你学过的），打包成 APK；不用学安卓原生（Java/Kotlin + Android Studio） |
| 工具 | HBuilderX（DCloud 官方免费 IDE），负责运行预览和云打包 APK |
| 语法 | Vue3 **选项式 API**（`data()` / `methods` / `computed`），最接近 Vue2 的写法，最好懂 |

**和普通 Vue 的区别（就一点）**：把 HTML 标签换成 uni 的组件 —— `div`→`view`、`span`→`text`、`img`→`image`，`uni.request` 替掉 `axios`。其他（`v-if`、`v-for`、`@click`、生命周期）全一样。

**一个页面长这样**（`pages/search/search.vue` 简化版）：

```vue
<template>
  <view class="page">                        <!-- view 相当于 div -->
    <input v-model="keyword" @confirm="doSearch" />
    <view v-for="(b, i) in results" :key="i" @click="addToShelf(b)">  <!-- v-for 列表渲染 -->
      <text>{{ b.name }}</text>              <!-- text 相当于 span，{{ }} 插值 -->
      <text>{{ b.author }}</text>
    </view>
    <text v-if="results.length === 0">没有结果</text>   <!-- v-if 条件渲染 -->
  </view>
</template>

<script>
const api = require('@/common/api.js')     // 引入后端接口封装
export default {
  data() { return { keyword: '', results: [] } },    // 响应式数据
  methods: {
    doSearch() {
      api.search(this.sourceId, this.keyword)        // 调后端（返回 Promise）
        .then(list => { this.results = list })       // 成功：赋值，界面自动刷新
        .catch(err => uni.showToast({ title: err, icon: 'none' }))  // 失败：弹提示
    }
  }
}
</script>
```

**必须掌握的几个点：**

| 概念 | 写法 | 说明 |
|---|---|---|
| 响应式数据 | `data() { return {...} }` | 改了数据界面自动更新 |
| 事件 | `@click="方法名"` | 事件绑定 |
| 双向绑定 | `v-model="变量"` | 输入框 ↔ 变量 |
| 列表 | `v-for="(item, i) in list" :key="i"` | 循环渲染 |
| 条件 | `v-if` / `v-else` | 显示隐藏 |
| 计算属性 | `computed: { xx() {...} }` | 依赖数据算出来的值（带缓存） |
| 生命周期 | `onLoad(params)` / `onShow()` / `onUnload()` | 页面加载/显示/卸载时执行 |

### 2.2 uni 本地存储（数据存手机）

**是什么**：App 端本地存数据，相当于网页的 localStorage，但是**同步 API**（不用 await）。

```javascript
uni.setStorageSync('bookshelf', list)        // 存（自动转 JSON）
const list = uni.getStorageSync('bookshelf')  // 取（自动转回对象）
uni.removeStorageSync('key')                  // 删
```

**本项目存的 key（用户数据全在手机本地）：**

| key | 存什么 |
|---|---|
| `bookshelf` | 书架数组 |
| `progress_{bookId}` | 每本书读到第几章、滚动位置 |
| `chapter_{bookId}_{idx}` | 单章正文缓存（下载/离线就是存这个） |
| `chapters_{bookId}` | 整本目录缓存 |
| `download_{bookId}` | 下载任务进度 |
| `reader_settings` | 全局阅读偏好（字号/主题/翻页方式） |
| `server_url` | 后端地址 |

> **设计要点**：书架/进度/设置全在手机，服务器只存书源规则 —— 所以**后端挂了或重启，你的书架和进度一点都不受影响**。

### 2.3 uni.request（调后端接口）

**是什么**：uni 的网络请求 API，相当于网页的 `fetch`/`axios`。

```javascript
uni.request({
  url: server() + '/api/search',
  method: 'GET',
  data: { sourceId: 1, keyword: '斗破' },
  success(res) {
    if (res.data.code === 0) { /* 成功，用 res.data.data */ }
    else { /* 失败，res.data.msg 是错误信息 */ }
  },
  fail(err) { /* 网络层失败 */ }
})
```

本项目在 `common/api.js` 里**统一封装**了一遍：把「判断 code、提取 data、拼错误提示」重复逻辑收在一个地方，页面里只写 `api.search(...).then(list => ...)`，干净。

```javascript
function get(path, params) {
  return new Promise((resolve, reject) => {      // 包成 Promise，调用处用 .then/.catch
    uni.request({
      url: server() + path, method: 'GET', data: params || {},
      success(res) {
        const body = res.data
        if (body && body.code === 0) resolve(body.data)   // 成功
        else reject((body && body.msg) || '接口返回异常')   // 失败
      },
      fail() { reject('连不上服务器，请检查网络或服务器地址') }
    })
  })
}
```

> **Promise 是什么**：代表「一个还没完成、将来会有结果的异步操作」。`.then(成功回调)`、`.catch(失败回调)`。网络请求都是异步的，所以用它。

### 2.4 HTML / CSS（页面长什么样）

**是什么**：网页的骨架（HTML）和样式（CSS）。uniapp 里也是这套，只是标签换成 uni 组件。

/* 本项目 uni.scss 里的品牌色变量 */

| 定位 | `position: relative/absolute/fixed` |
| 常用属性 | `color`、`background`、`border-radius`、`font-size` |
| 单位 | `rpx`（uniapp 专属，按屏幕宽自适应）、`vw/vh`、`%`、`px` |

> 本项目**不引第三方 UI 库**（如 uView），全部手写基础 CSS —— 目的是练基本功、减少依赖。

### 2.5 页面路由与 Tab（pages.json）

**是什么**：uniapp 的页面登记表，相当于 Vue Router 的配置文件。

```json
{
  "pages": [
    { "path": "pages/bookshelf/bookshelf", "style": { "navigationBarTitleText": "遇夏小说" } },
    { "path": "pages/reader/reader", "style": { "navigationStyle": "custom" } }  // 自定义导航栏
  ],
  "tabBar": {
    "list": [
      { "pagePath": "pages/bookshelf/bookshelf", "text": "书架", "iconPath": "static/tabbar/shelf.png" },
      { "pagePath": "pages/mine/mine", "text": "我的", "iconPath": "static/tabbar/mine.png" }
    ]
  }
}
```

跳转：

```javascript
uni.navigateTo({ url: '/pages/reader/reader?bookId=' + id })   // 打开新页面（带参数）
uni.navigateBack()                                             // 返回
// 接收参数：被打开页面在 onLoad(params) 里拿 params.bookId
```

> **新增页面必做**：在 `pages.json` 的 `pages` 数组里登记，否则页面访问不到。

## 3. 用到的「设计模式 / 编程习惯」

这些不算框架，但项目里到处都是，认识了代码就好懂：

| 名字 | 项目里的样子 | 通俗说 |
|---|---|---|
| 分层架构 | Controller → Service → Mapper | 接口层只管收发、业务层管逻辑、数据层管数据库，各管各的 |
| 封装 | `api.js` 统一包请求、`Result` 统一返回格式 | 重复的东西只写一遍 |
| 规则驱动 | 书源规则存成 JSON，解析时按规则取值 | **不改代码就能适配新网站**（加个书源就行） |
| 优先级兜底 | 本地缓存优先 → 网络；mock 源兜底 | 先快后慢、先本地后远端，保证能跑 |
| 防御式编程 | 防死循环（visited 集合）、防越界、抓取重试 | 网络环境不可控，代码要能扛住异常 |
| 单例 | Spring 里的 Service/Controller 默认单例 | 一个类只创建一个对象，全项目共用 |

## 4. 术语速查表（看到不认识的就查这里）

| 术语 | 一句话解释 |
|---|---|
| **SSM** | Spring + SpringMVC + MyBatis，传统 Java Web 三件套（你正在学的） |
| **Spring Boot** | SSM 的自动化版本，开箱即用 |
| **IoC / 依赖注入** | 对象不由你 new，Spring 创建好送给你（`@Autowired` / 构造器注入） |
| **Bean** | 被 Spring 管理的对象 |
| **REST / RESTful** | 用 HTTP 的 GET/POST/PUT/DELETE 表达查/增/改/删的接口风格 |
| **JSON** | 一种数据格式，前后端传数据都用它 |
| **ORM** | 对象 ↔ 数据库表的映射（一个类 = 一张表） |
| **Mapper** | ORM 里负责执行数据库操作的那个接口 |
| **CRUD** | 增删改查（Create/Read/Update/Delete） |
| **DOM** | 网页元素组成的树结构，Jsoup/CSS 选择器都在这棵树上找节点 |
| **CSS 选择器** | 定位网页元素的语法，如 `#id`、`.class`、`a[rel=x]` |
| **UA (User-Agent)** | 请求头里标记「我是什么浏览器」，伪装它可绕部分反爬 |
| **Referer** | 请求头里标记「从哪个页面跳来的」，防盗链会检查它 |
| **Promise** | JS 里代表「将来会有结果的异步操作」的对象 |
| **异步** | 不阻塞等结果，等到了再回调（网络请求都是异步） |
| **rpx** | uniapp 的响应式单位，750rpx = 屏幕宽度 |
| **APK** | 安卓 App 安装包 |
| **jar** | Java 打包产物，可独立运行的程序包 |
| **依赖 (dependency)** | 项目用到的第三方库 |
| **内嵌 Tomcat** | 打包在程序里的 Web 服务器，不用单独装 |

## 5. 学习优先级建议（按这个项目来）

如果你想自己看懂/改这个项目，**建议的学习顺序**（都是免费 B 站资源，直接搜关键词）：

1. **Java 基础** → 语法、集合、异常、IO（必需）
2. **MySQL / JDBC** → 数据库基础和 Java 连库（必需，理解 Mapper 的前提）
3. **MyBatis → MyBatis-Plus** → 先懂手写 SQL，再用 Plus 的省事方法（本项目只用了单表 CRUD）
4. **Spring → SpringMVC → Spring Boot** → 重点理解 IoC/依赖注入、注解、REST 接口
5. **HTML / CSS / JavaScript** → 前端基础，Vue 的前提
6. **Vue3（选项式）** → 组件、响应式、事件、生命周期
7. **uniapp** → 把 Vue 变成 App，看官方文档 + 写 demo 页

> **本项目的定位**：它把上面这些都串起来了（后端 Spring Boot + MyBatis-Plus + Jsoup，前端 uniapp + Vue3），是一个**能跑通的全栈小项目**。看不懂某个文件时，回来查这份文档对应的技术点。

## 6. 项目里没用、但你可能听过的技术（避免走弯路）

| 技术 | 为什么本项目不用 |
|---|---|
| Spring Cloud / 微服务 | 个人软件，单机就够，微服务是几十人团队才需要 |
| Redis | 没有高并发/缓存需求，本地存储 + SQLite 够用 |
| MySQL | 数据量极小（就几条书源），SQLite 单文件更省事 |
| Vue Router / Vuex / Pinia | uniapp 用 `pages.json` 自带路由，状态用本地存储就够 |
| Element UI / uView | 界面简单，手写 CSS 更轻、更能练基本功 |
| Kotlin / Android Studio | 用 uniapp 就绕开了安卓原生开发 |
| Docker / K8s | 单机部署，`java -jar` + Nginx 足够 |
