# 05 部署文档（阿里云 + 域名 + APK）

> 目标形态：手机装 APK → 填服务器地址 → 正常搜书看书。

## 0. 先选方案：两种部署方式

| | **方案 A：快速跑通**（建议先用） | **方案 B：正式上线** |
|---|---|---|
| 服务器地址 | `http://服务器IP:8080` | `https://book.你的域名.com` |
| 需要域名 | ❌ 不需要 | ✅ 需要（国内服务器还要 ICP 备案） |
| 需要 HTTPS | ❌ 不需要 | ✅ 需要（Let's Encrypt 免费） |
| 耗时 | 约 10 分钟 | 约 40 分钟 |
| 适合 | 自己先用起来、验证功能 | 长期使用、更安全 |
| App 端要求 | **必须保留** `app/AndroidManifest.xml`（允许明文 HTTP） | 可删除该文件 |

**推荐路线**：先用**方案 A** 把整条链路跑通（能搜书能看书），跑顺了再升级**方案 B** —— 升级时只改服务器地址，App 不用重装。

- **方案 A**：做 §2（装环境）→ §3（跑后端）→ 安全组放行 **8080** → §5（打包 APK）
- **方案 B**：完整做 §2 → §3 → §4（域名 + Nginx + HTTPS）→ §5

> 下文命令以 CentOS/Ubuntu 为例，差异处已标注。

## 1. 准备清单

- [ ] 阿里云 ECS（1核2G 起步即可），能 SSH 登录
- [ ] 安全组放行：22（SSH）；方案 A 再放 **8080**，方案 B 放 **80、443**
- [ ] 域名一个，已完成 ICP 备案（**仅方案 B 需要**；阿里云绑定域名到国内服务器必须备案）

## 2. 服务器装环境

```bash
# Ubuntu
apt update && apt install -y openjdk-17-jre nginx
# CentOS: yum install -y java-17-openjdk nginx

java -version   # 确认 17.x
```

> jar 按 Java 8 目标编译，JDK 8/11/17/21 都能跑，装 17 是长期支持。

## 3. 上传并运行后端

> **先回答一个常见疑问**：「Spring Boot 自带 Tomcat，是不是把 jar 丢服务器就能跑？」
>
> **基本对，但有 3 点要注意：**
> 1. ✅ **jar 是自包含的** —— 内嵌 Tomcat + 所有依赖都打进去了。服务器**不需要装 Tomcat、不需要装 Maven**，只要装了 **JDK** 就能跑。
> 2. ⚠️ **要让它后台常驻** —— 直接 `java -jar` 的话，SSH 一断开服务就停了。要用下面的 systemd（开机自启 + 崩溃自动拉起）。
> 3. ⚠️ **注意运行目录** —— SQLite 路径是 `data/mybooks.db`（**相对当前工作目录**）。必须固定在 `/opt/mybooks/` 下运行，数据库才会落在 `/opt/mybooks/data/mybooks.db`；乱换目录会出现「书源莫名消失」。
>
> 另外：**服务器安全组要放行端口**（用 Nginx 放 80/443；直接跑 8080 就放 8080）。

```bash
# 本地打包
cd backend && mvn clean package -DskipTests
# 产物 backend/target/books-1.0.0.jar

# 上传（Windows 用 scp 或 WinSCP 图形工具）
ssh root@服务器IP "mkdir -p /opt/mybooks"
scp target/books-1.0.0.jar root@服务器IP:/opt/mybooks/
```

用 systemd 常驻（推荐，开机自启 + 挂了自动拉起）：

```bash
# /etc/systemd/system/mybooks.service
[Unit]
Description=Yuxia Books Backend
After=network.target

[Service]
WorkingDirectory=/opt/mybooks
ExecStart=/usr/bin/java -jar /opt/mybooks/books-1.0.0.jar
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now mybooks
curl http://127.0.0.1:8080/api/health   # 服务器上自测
```

> SQLite 数据文件在 `/opt/mybooks/data/mybooks.db`（相对 jar 的工作目录），备份=复制这个文件。

## 4. 域名解析 + Nginx + HTTPS

1. 阿里云控制台 → 云解析 DNS → 给域名加 A 记录指向服务器 IP（如 `book.你的域名.com`）
2. Nginx 配置 `/etc/nginx/conf.d/mybooks.conf`：

```nginx
server {
    listen 80;
    server_name book.你的域名.com;
    client_max_body_size 10m;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_read_timeout 60s;
    }
}
```

```bash
nginx -t && systemctl reload nginx
# 浏览器访问 http://book.你的域名.com/api/health 验证
```

3. HTTPS（免费证书，Let's Encrypt）：

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d book.你的域名.com
# 按提示填邮箱同意协议，选重定向到 HTTPS，自动续期已配好
```

## 5. App 打包 APK（HBuilderX 云打包）

### 5.0 打包前必看：三件事

| 事项 | 怎么做 | 不做会怎样 |
|---|---|---|
| **① DCloud AppID** | HBuilderX 打开项目后会提示「未配置 AppID，是否自动生成」，点**是**（需先登录 DCloud 账号） | 无法云打包 |
| **② 允许明文 HTTP** | 项目根目录已有 `app/AndroidManifest.xml`（**本项目已提供，无需操作**） | 后端用 `http://` 时 App 连不上（安卓 9+ 限制） |
| **③ 图标（可选）** | 把 `app/static/logo.png` 换成自己的图，或在 HBuilderX 可视化界面配 | 用默认图标，不影响功能 |

> **关于 ② 为什么要做**：安卓 9（API 28）起系统默认禁止 App 发 HTTP 明文请求，uni-app 云打包默认 `targetSdkVersion=28`，正好踩在限制上。若后端地址是 `http://IP:8080`，App 请求会被系统直接拦掉，表现为「连不上服务器」。`app/AndroidManifest.xml` 里的 `usesCleartextTraffic="true"` 就是放开它。
> **后端上线 HTTPS 后，这个文件可以删掉**（留着也无副作用）。

### 5.1 先跑通，再打包（推荐顺序）

别直接云打包，先用「运行到手机」验证功能，省得打包完才发现问题：

1. HBuilderX → 文件 → 导入 → 从本地目录导入 → 选 `app/` 文件夹
2. 手机开「开发者选项 → USB 调试」，数据线连电脑
3. 菜单 **运行 → 运行到手机或模拟器** → 选你的手机
   - 首次会自动安装「HBuilderX 标准基座」（手机上会多一个 HBuilderX App），等它跑起来
4. App 里进 **我的 → 关于 → 服务器地址**，填电脑的**局域网 IP**（电脑上 `ipconfig` 查 IPv4，如 `http://192.168.1.5:8080`），点「测试连接」应显示 ✓
5. 走一遍完整流程：搜索 → 加入书架 → 阅读 → 换字号/主题 → 目录 → 下载 → 断网还能读
6. 都正常了，再去云打包

> 手机和电脑必须在同一个 WiFi 下，且电脑防火墙要允许 8080 端口（Windows 首次会弹窗，点「允许」）。

### 5.2 云打包正式 APK

1. HBuilderX 菜单 **发行 → 原生App-云打包**
2. 弹窗里填：
   - **安卓包名**：`com.yuxia.books` ← 必须和 `app/AndroidManifest.xml` 里的 `package` **完全一致**
   - **证书**：选「**使用公共测试证书**」（自用足够；以后要正式证书可用 DCloud 在线生成）
   - 不需要的选项（广告等）都取消勾选
3. 点「打包」，等 3~10 分钟
4. 完成后控制台给出**下载链接/二维码** → 下载 APK 或手机扫码安装
5. 手机上装好后，进「我的 → 关于 → 服务器地址」填你的服务器地址

> **打包失败常见原因**：没登录 DCloud 账号 / 包名与 AndroidManifest.xml 不一致 / AndroidManifest.xml 格式错误。打包日志会写明原因，按日志改即可。

### 5.3 换图标（可选，想让 App 好看点）

1. HBuilderX 里双击 `app/manifest.json` → 切到「App图标配置」
2. 选一张 512×512 以上的 PNG，点「自动生成所有图标并替换」
3. 重新云打包生效

## 6. 更新迭代流程

- 后端改了：重新 `mvn clean package -DskipTests` → scp 上传覆盖 → `systemctl restart mybooks`
- App 改了：HBuilderX 重新云打包 → 手机覆盖安装（本地书架数据不丢）

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| App 连不上后端 | 先浏览器访问 `https://域名/api/health`；不通查安全组 80/443、Nginx、备案 |
| 搜索无结果 | 书源规则不适配该站 → 书源管理高级模式改选择器，或换镜像站 |
| 封面不显示 | 该站防盗链，走后端 `/api/image` 代理可解决大部分 |
| 证书过期 | `certbot renew --dry-run` 检查自动续期 |
