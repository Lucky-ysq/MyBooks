# 02 技术架构文档

## 1. 系统架构

```
┌──────────────────────┐   HTTP/JSON    ┌───────────────────────┐   HTTP+Jsoup   ┌──────────────┐
│  遇夏小说 App (安卓)   │ ─────────────> │  Spring Boot 后端      │ ─────────────> │  小说网站书源  │
│  uniapp + Vue3       │ <───────────── │  (阿里云 ECS + 域名)   │ <────────────── │  (HTML 网页)  │
│                      │    统一 JSON     │  MyBatis-Plus+SQLite  │    原始 HTML    └──────────────┘
│  本地存储(uni storage)│                 │  书源规则表(唯一一张表)  │
│  书架/进度/下载/设置    │                 └───────────────────────┘
└──────────────────────┘
```

要点：
- App **不直接**访问小说网站（避免跨域/防盗链/证书问题），统一走自家后端
- 后端职责：存书源规则 + 按规则抓取解析小说站 + 输出统一 JSON
- 用户数据 99% 在手机本地，后端重启/迁移不影响书架

## 4. API 设计（统一前缀 /api，返回统一 Result 格式）

统一返回：`{ "code": 0, "msg": "ok", "data": ... }`，code=0 成功，非 0 失败（msg 为人话错误信息）。

| 接口 | 方法 | 参数 | 返回 data | 说明 |
|---|---|---|---|---|
| `/api/health` | GET | - | `{version}` | 健康检查 |
| `/api/sources` | GET | - | 书源数组 | 列表（含 enabled、isDefault） |
| `/api/sources` | POST | 书源 JSON | 新书源 | 新增（简单模式只传 name+baseUrl+用模板） |
| `/api/sources/{id}` | PUT | 书源 JSON | - | 修改 |
| `/api/sources/{id}` | DELETE | - | - | 删除（至少保留一个书源） |
| `/api/sources/{id}/default` | POST | - | - | 设为默认源（同时置为启用，其他源取消默认） |
| `/api/sources/{id}/test` | GET | keyword=斗破 | 搜索结果数组 | 书源连通性测试 |
| `/api/search` | GET | sourceId, keyword | `[{name, author, bookUrl, coverUrl, intro}]` | 搜索图书 |
| `/api/book/detail` | GET | sourceId, bookUrl | `{name, author, coverUrl, intro, latestChapter, updateTime}` | 书籍详情 |
| `/api/book/chapters` | GET | sourceId, bookUrl | `[{title, chapterUrl}]` | 目录 |
| `/api/book/content` | GET | sourceId, chapterUrl | `{title, paragraphs:[...], prevUrl, nextUrl}` | 章节正文（已净化） |
| `/api/image` | GET | url | 图片二进制 | 封面代理（处理防盗链 Referer） |

说明：
- bookUrl/chapterUrl 传完整 URL（后端按书源 baseUrl 补全后抓取），App 端原样保存
- content 接口返回 paragraphs 数组，App 端按段落渲染
- **`id` / `sourceId` 在 JSON 里是字符串**（如 `"2110518753123545091"`），不是数字。原因见下方「长整型 id 必须序列化成字符串」。App 端拿到后原样透传即可，不要做 `Number()` 转换或数值运算。

### 长整型 id 必须序列化成字符串（重要，踩过坑）

书源主键由 MyBatis-Plus 雪花算法生成，是 **19 位 Long**（如 `2110518753123545091`）。
JavaScript 的 `Number` 安全整数上限只有 `2^53-1 = 9007199254740991`（16 位），App 端 `uni.request` 内部 `JSON.parse` 之后**末几位会被静默抹平**：

```
数据库真实 id  : 2110518753123545091
JS 解析后      : 2110518753123545000   ← 末三位没了
```

App 再把这个变形的 id 传回后端，就查不到书源，报 **「书源不存在：id=2110518753123545000」**。

解决：`config/JacksonConfig.java` 里统一把 Long 序列化成 JSON 字符串。
后端 `@RequestParam Long` / `@PathVariable Long` 声明不变，接收字符串仍能自动转换，**App 端一行都不用改**。

## 5. 书源规则格式（BookSource，核心设计）

存 SQLite `book_source` 表，规则主体是 **JSON 字符串**（rules 字段），结构：

```json
{
  "charset": "utf-8",
  "search": {
    "url": "/search.php",       "method": "POST",
    "body": "searchkey={{key}}",
    "list": ".novelslist2 li",
    "name": "h3 a",             "bookUrl": "h3 a@href",
    "author": ".author",        "intro": ".intro"
  },
  "detail": {
    "name": "#info h1",          "author": "#info p:eq(0)",
    "intro": "#intro",           "cover": "#fmimg img@src",
    "latestChapter": "#info p:eq(3) a"
  },
  "toc":   { "list": "#list dd a", "title": "text", "chapterUrl": "href",
             "url": "index_1.html", "nextPage": "#list a.index-container-btn" },
  "content": { "selector": "#content", "remove": ".ad, script, style",
               "scriptDecode": false, "nextPage": "a.next" }
}
```

选择器语法（基于 CSS 选择器，实现见 `util/RuleParser.java`）：
- `xxx` = CSS 选择器取元素文本
- `xxx@href` / `xxx@src` = 取属性（相对地址后端自动按页面 URL 补全）
- `xxx@own` / `@own` = 取元素自身文本（不含子标签）。如 `<a><span>免费</span>第1章 火神重生</a>` 只取「第1章 火神重生」
- `href` / `src` = 取元素自身属性（目录列表里常用；后端会补成绝对 URL）
- `xxx@onclick:url` = **从属性值里抠链接**。移动站常把书链接藏在 onclick 里、根本没有 `a[href]`，如
  `onclick="newWebView('/b/236324.html', '', '')"` → 规则写 `@onclick:url` 就能抠出来并补成绝对 URL
- `规则##正则##替换文本` = **清洗**（沿用 Legado 写法，成对出现；末尾落单的正则表示删除匹配内容）。
  例：`.v-words span:eq(0)##作者：` 把「作者：青铜」变成「青铜」
- `{{key}}` = 搜索关键字占位符
- 多个规则可用逗号分隔，依次尝试，第一个取到值的生效

**toc 的可选字段（适配「目录独立页 + 分页」的站点）：**
- `url`：目录页地址（相对地址基于 bookUrl 补全）。有的站完整目录不在详情页，如 `/book/1/index_1.html`
- `urlRule`：目录页链接的**选择器**（优先于 `url`）。用于目录页路径不固定的站——阅友小说详情页只给前 3 章预览，
  完整目录在 `/c/{id}.html`，写 `"urlRule": ".sumchapter a"` 就能从「查看目录」链接跳过去
- `nextPage`：目录翻页链接的选择器。后端循环抓取并拼接，自动跳过 `javascript:void(0)` 这类禁用按钮，最多 100 页
- `title` / `chapterUrl` 缺省为 `text` / `href`

**content 的注意点（适配「正文 JS 加密 + 章内分页」的站点）：**
- 正文容器**取全部匹配并依次拼接**，不是只取第一个。有的站把章内分页 1/5~5/5 全塞在同一个 HTML 的多个容器里
  （阅友小说是 `.con` × 5），只取第一个会丢掉 4/5 的内容
- `scriptDecode: true`：正文以 base64 藏在容器内 `<script>` 里时开启，后端自动解码拼接（部分站用 JS 解码正文来防抓取）；不填则按普通 HTML 正文处理
- `nextPage`：章内分页「下一页」选择器。后端有**安全停止**逻辑：下一页链接必须仍是本章的分页（文件名形如 `5027049_2.html`）才继续，否则停止，防止把后续整本书拼进来（最多 30 页）

**简单模式/模板**：添加书源只填 `name + baseUrl`，后端用「笔趣阁通用模板」的默认规则填充 rules。高级模式直接改 rules JSON（App 端给文本编辑框 + 字段说明）。

内置默认源：后端启动时**表为空**则插入三条（已有数据不会重复插）——
1. 「本地测试源」`mock://local`：后端自己生成 3 本假数据，保证无外网也能全流程调试
2. 「笔趣阁·真实源(测试)」`https://www.bqg70.com`（`SourceTemplates.BQG70_RULES`），M5 实测适配
3. 「阅友小说」`http://m.suixkan.com`（`SourceTemplates.YUEYOU_RULES`）：移动站、国内可直连，
   规则取自 xiu2/yuedu 的 Legado 书源订阅并重写——那份订阅共 22 个源，但 17 个用了 `<js>` 脚本、
   其余多数需梯子或人机验证，**只有它是纯 CSS、无 JS、无 XPath 且实测可用的**。
   它也是「规则引擎三个新能力」的验证样本：onclick 抠链接、`##` 清洗、多容器正文拼接

> **为什么不能直接导入 Legado 书源订阅？** 两者格式完全不同：Legado 用 `class.x.0@tag.a.1@text` 这种私有简写，
> 还支持 `<js>` 脚本块和 JSONPath（`$.author`），而本项目只支持标准 CSS 选择器。订阅地址是「书源列表文件」，
> 不是「小说网站网址」——把它填进「添加书源」会让后端拿笔趣阁模板去拼 `.../shuyuan/search.php`，站点返回 403。

## 6. App 本地存储 key 设计（uni.setStorageSync）

| key | 内容 | 结构 |
|---|---|---|
| `bookshelf` | 书架数组 | `[{id, name, author, cover, sourceId, bookUrl, totalChapters, latestChapter, lastChapterIndex, lastChapterTitle, lastReadTime, addedTime}]` |
| `progress_{bookId}` | 每本书进度 | `{chapterIndex, scrollTop}` |
| `reader_settings` | 全局阅读偏好 | `{fontSize, lineHeight, bgTheme, pageMode, nightMode, keepScreenOn}` |
| `server_url` | 后端地址 | 字符串，默认 `http://127.0.0.1:8080`（首启动引导填写） |
| `chapters_{bookId}` | 整本目录缓存 | `[{title, chapterUrl}]`（加书架时写入；阅读/下载/目录页都用它，避免重复拉目录） |
| `chapter_{bookId}_{idx}` | 单章缓存 | `{title, paragraphs}`（阅读缓存与下载的章节都存这里，断网可读） |
| `download_{bookId}` | 下载任务状态 | `{bookId, sourceId, bookUrl, total, chapters, queue:[待下章号], done:[已下章号], status}`，status = running/paused/done |

说明：
- `bookId` = bookUrl 的散列（App 端 djb2 字符串 hash，见 `common/util.js`），保证同源同书唯一
- `bookshelf` 加书架时写入全字段；阅读时只更新 `lastChapterIndex / lastChapterTitle / lastReadTime`（阅读百分比由前端实时算，不落库）
- `latestChapter` 是加书架时抓到的站点最新章节名，不随阅读更新
- 预留（当前未使用）：`bookmeta_{bookId}` —— 设计时留给「书籍详情缓存（封面/简介）」，V1 直接复用 `bookshelf` 里的字段，故未实现

## 7. 阅读器交互设计（V1 实际实现）

- **点击区域**：点击正文任意位置 → 呼出/隐藏工具栏（V1 简化为整屏点击，未做「中央 60% / 两侧 20%」分区）
- **翻页方式**：
  - 上下滚动：`scroll-view` 自然滚动，滚动位置即进度（`scroll-top` 只在跳章/恢复时赋值，避免回跳）
  - 左右滑动：`swiper` 每屏一章，滑动窗口 3 章（上一章/当前章/下一章）；程序改 `current` 时用锁吞掉一次 `change` 事件，避免死循环
  - 两种模式都可用工具栏「上一章 / 下一章」按钮切章
- **界面设置**：字号 12~36（A- / A+ 按钮）；行距 1.2~2.4（slider，内部按 ×10 取整映射）
- **主题**：5 套背景色（white / paper / green / gray / black）+ 对应文字色；夜间模式 = 切到 black 主题的快捷开关
- **屏幕常亮**：`uni.setKeepScreenOn()`
- **进度保存**：滚动位置节流记录，`onHide` / `onUnload` / 返回时写 `progress_{bookId}`

## 8. 离线下载队列设计（App 端）

- 目录页发起：选择范围 → 生成待下章号列表 → 写入 `download_{bookId}`（status=running）
- 全局下载器（App.vue 挂载，简单 setInterval 轮询队列）：每次并发 2 章，逐章调 `/api/book/content` 存入 `chapter_{bookId}_{idx}`，更新 done 数组
- 暂停 = status=paused（轮询跳过）；继续 = running；删除缓存 = 清掉对应 chapter_* key
- 阅读时先查本地 chapter_*，命中直接渲染（断网可用）

## 9. 关键流程

**加书流程**：搜索页输入 → `/api/search` → 点结果 → `/api/book/detail` 弹详情 → 加入书架（写 bookshelf + 调 `/api/book/chapters` 记录总章数）→ 书架可见

**阅读流程**：点书架书 → 读 progress_{bookId} 得章号 → 查本地 chapter_* → 未命中调 `/api/book/content`（并写缓存）→ 渲染 → 退出/切章时保存 progress

**部署形态**：阿里云 ECS 跑 jar（8080，仅本机监听）+ Nginx 443 反代（HTTPS 域名）→ App 填 `https://域名`。详见 05 文档。
