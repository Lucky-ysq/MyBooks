### 会话 6（2026-10-15）
**主题：M5 真实书源联调（bqg70.com 打通）+ 后端三个适配能力 + 两个隐藏 bug 修复**

**背景**：M5 原计划「找一个可访问的笔趣阁镜像站实测」。选定 `https://www.bqg70.com` 作为开发期真实源，逐层摸清站点结构后发现它不是标准笔趣阁模板，需要给后端补三个通用能力。

**站点结构摸底结论（bqg70.com）：**
- 搜索：POST `/search.html`，参数 `s=关键字`；列表项 `.item`，书名/链接 `dt a`，作者 `.btm`（own text），简介 `dd`，封面 `.image img@data-original`
- 详情：字段都在 `og:novel:*` / `og:image` 的 meta 上（最干净，不怕改版）
- 目录：不在详情页，在 `/book/{id}/index_1.html`，**每页 100 章分页**，章节链接 `#list a[rel=chapter]`
- 正文：`#content` 内的 `<script>` 里是 **base64 加密正文**，且**章内还分页**（`5027049.html` → `5027049_1.html` → …），末页的「下一页」实际指向下一章（不能盲目跟随）

**后端新增的三个通用能力（不只服务这一站）：**
1. **目录翻页**（`TocRule` 新增 `url`、`nextPage`）：目录可在独立页面且分页，后端按 `nextPage` 选择器循环拼接，带 visited 防死循环（上限 100 页）
2. **正文翻页 + 安全停止**（`ContentRule` 新增 `nextPage`）：章内分页自动拼接；`isSameChapterPage()` 用「章文件名 + `_数字` 后缀」正则判断，一旦下一页指向别的章节就停，避免把整本书拼进来（上限 30 页）
3. **script base64 解码**（`ContentRule` 新增 `scriptDecode`）：对正文容器内 `<script>` 中形如 `'...'` 的长 base64 串解码后按段落拼接（正则 `['"]([A-Za-z0-9+/=]{16,})['"]`）

**修复的两个隐藏 bug（都是在这次真实源联调中暴露的）：**
1. **`absUrl` 把文本值拼成 URL**（`RuleParser.absolute`）：原来无条件调 `el.absUrl()`，导致 `<meta content="梦入斗破">` 被拼成 `https://www.bqg70.com/book/10965/梦入斗破`。修复：只有值看起来像地址（`http`/`/`/`./`/`../` 开头）才补全，否则原样返回。→ 详情接口的 name/author/latestChapter 恢复正常
2. **目录章节链接未补全为绝对 URL**（`BookService.chapters`）：规则用裸 `href` 时 `RuleParser` 只返回原始相对值（`/book/10965/5027049.html`），App 端原样保存后回传会导致后续正文抓不到。修复：目录循环里对每章链接调 `resolveUrl(current, chapterUrl)` 补全

**其它适配：** `JsoupFetcher` 全局信任 SSL 证书（小说镜像站证书链普遍不全）+ 抓取失败自动重试 1 次（超时 20s）；新增 `SourceTemplates.BQG70_RULES` 模板，内置第二条示例源改为指向 bqg70.com 真实源（enabled=true）。

**新增文档：** `docs/06-技术栈总览.md` —— 完整列出项目用到的全部技术（Spring Boot / MyBatis-Plus / SQLite / Jsoup / Maven / uniapp+Vue3 / uni存储 / Promise 等），每个都写「是什么 + 项目里怎么用 + 关键语法 + 要学什么」，并附术语速查表和学习优先级，方便回顾。

**本机环境坑（重要，后续会话必看）：**
- **WorkBuddy 宿主会注入 `SERVER__PORT=52311` 环境变量**，Spring Boot 宽松绑定会把它当作 `server.port`，导致后端随机换端口不监听 8080。解决：启动加显式参数 `java -jar target/books-1.0.0.jar --server.port=8080`（命令行参数优先级高于环境变量）
- 本机 Python 的 `urllib` 走了代理，直接请求 `127.0.0.1:8080` 会 502 Bad Gateway；**测本地接口一律用 curl**，别用 Python urllib
- Git Bash 终端里 `curl -d` 发中文会变 GBK 乱码（老问题）；用 `-G --data-urlencode` 传中文参数

### 会话 10（2026-10-15 下午）：真机白屏 + 搜书报「书源不存在」两个 bug

#### 问题 1：真机页面全白，只剩底部导航栏

**根因**：项目是 uni-app **Vue3**（`manifest.json` `vueVersion:"3"` + `createSSRApp`），构建走 vite，而 `app/` 工作区文件是**旧版本**（CommonJS `require` / `module.exports`）。
vite 环境没有 `require`，运行时抛 `ReferenceError: require is not defined`；`App.vue` 顶层那句 `require('./common/downloader.js')` 在**模块求值阶段**就炸 → App 组件注册失败 → 整页 JS 不渲染；tabBar 是原生控件，所以它还在。

**处理**：`app/` 下 11 处 `require()` / `module.exports` 统一改为 `import` / `export default`（3 个 common 模块 + App.vue + 7 个页面）。

**⚠️ 关键发现**：改完 `git diff HEAD -- app/` 是**空的** —— 说明 **HEAD 里本来就是 ESM，是工作区被回退成了旧版本**。
这不是新引入的 bug，而是工作区版本错乱。
**排查纪律**：遇到「代码看着没问题、但行为像旧版本」的情况，先跑 `git status` + `git diff HEAD --stat`，确认工作区是不是落后于 HEAD，别急着改代码。

#### 问题 2：搜书报「书源不存在：id=2110518753123545xxx」

**根因**：书源主键由 MyBatis-Plus 雪花算法生成，是 **19 位 Long**（`2110518753123545091`），而 JS `Number` 安全整数上限只有 `2^53-1`（16 位）。App 端 `uni.request` 内部 `JSON.parse` 后**末几位被静默抹平**：

```
数据库真实 id : 2110518753123545091
JS 解析后     : 2110518753123545000   ← 末三位没了
```

App 再把这个变形 id 传回后端 → `SourceService.getById()` 查不到 → 抛「书源不存在：id=…」。因为两个内置源都走同一个 `sourceId` 参数，所以**测试源和真实源全都搜不到**。

**处理**：新增 `backend/.../config/JacksonConfig.java`，把所有 `Long` 序列化成 JSON 字符串。
后端 `@RequestParam Long` / `@PathVariable Long` 声明**不用改**（接收字符串能自动转 Long），**App 端零改动**（前端所有 id 用法都是字符串拼接/真值判断，没有数值运算）。

**验证（重新打包 jar 并重启后全部通过）**：
